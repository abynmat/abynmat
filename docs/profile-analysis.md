**Common traits**

1. **A one-line promise** at the top of the README ("The simplest, fastest repository for …").
2. **A figure or a results table above the fold.** Readers decide in about 10 seconds.
3. **Reproducible in one command** with pinned dependencies and a fixed seed.
4. **Small, readable code.** Hundreds of lines, not thousands, and no hidden framework magic.
5. **Honest, measured claims.** Mean ± std over seeds, with baselines, including results where the fancy model *loses*.
6. **Consistent maintenance.** Meaningful commit messages, issues answered, a licence.

## 4. Publishing checklist

1. Set your **name, bio, location and a link** under GitHub Settings → Profile.
2. Create a repo named exactly `abynmat`, and push `abynmat/README.md` into it.
3. Projects are grouped into topical repos (language-models, ml-from-scratch, statistics, applied-data-science, graph-ml), one subfolder per project. For each repo:
   ```bash
   cd graph-ml
   git init -b main && git add . && git commit -m "GCN, GraphSAGE and GAT from scratch with Cora benchmarks"
   git remote add origin git@github.com:abynmat/graph-ml.git
   git push -u origin main
   ```
4. **Pin** the three projects. Add topics (`graph-neural-networks`, `pytorch`, `llm`, `fraud-detection`).
5. Fix or attribute `Data-Science-Projects` (see §1).
6. Before every push, check that nothing employer-related is in the repo:
   `git grep -i -E "amazon|aws|internal|confidential"` should return nothing.
   (Run it after `git add`, before `git commit`.)
